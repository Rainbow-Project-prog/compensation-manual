## 2. 最初のタスク: レビュー（ユーザー指定の3点）

実装に入る前に、Ultracode で以下の3点を検証し、**結果をユーザーに報告して承認を得ること**。
前セッションの成果物（コード・ドキュメント・レビュー修正のすべて）を**信用せず**、独立に再検証する。
特に「修正」が指摘を本当に解消しているか、新しいバグを持ち込んでいないかを敵対的に見ること。

### 2-1. 指示書の内容に間違いがないか

- `HANDOFF.md` / `README.md` / `RUNBOOK.md` / 本書の**すべての具体的な記述**（コマンド、ファイル名、
  挙動の説明、手順の順序）をコードと突き合わせる。前回レビューでドキュメント齟齬が7件確定した
  （修正済みのはずだが、修正後の再検証はされていない）。
- 特に: README の手順順序（SELECTORS を埋めてから `npm run login`）、PM2 の起動方法
  （`ecosystem.config.cjs` / Windows では `pm2 start npm` 不可）、RUNBOOK の終了処理の記述。

### 2-2. 今回のタスクを遂行するにあたっての内容の適切さ

このプロジェクトの目的（スマホから Lpro の顧客対応をする）に対して、設計・実装が適切かを評価する。
前セッションで**ユーザーの明示承認なしに行った設計変更**が3つある。妥当性を判断し、問題があれば指摘すること:

1. **初回配信ポリシーの変更**: 元仕様は「初回はその顧客の履歴を一切配らず既読扱い」。
   これだと新規顧客の初回メッセージが必ず消失するため（確定指摘 [0]）、
   「起動時に全会話をブートストラップ＋稼働中に初めて現れた会話は末尾 `BOOTSTRAP_TAIL` 件（既定5）配信」に変更した。
2. **トピックの遅延作成**: 元実装は未読検知のたびにトピック作成。空トピック量産を防ぐため
   「配信すべきメッセージがある時だけ作成」に変更した。副作用: オペレータ側から会話を**先に**始めることはできない。
3. **件数減少サイクルのスキップ**: 元実装は件数が減ったら既読を下方修正（→復帰時に旧メッセージ大量再配信）。
   「減少は部分レンダリングとみなしてそのサイクルは何もしない」に変更した。

また、アーキテクチャ自体の適切さ（Playwright スクレイピング + 件数ベース検知 + Telegram トピック）を、
§4 の残タスクと合わせて評価すること。

### 2-3. その他、Fable 5 で検討すべき事項

- **リスクの再確認**: この自動化は Lpro の利用規約に抵触する恐れがあり、Lpro 自体の運用（LINE 無料アカウント
  大量複製）は LINE 規約違反で一括凍結リスクがある（HANDOFF §1 に記録済み。ユーザー承知の上）。
  顧客の会話データを Telegram に転送するため、グループは非公開・最小メンバー運用が前提。
  実装時に**データを増やして外に出す変更**（ログへの会話全文出力等）をしないよう注意。
- **Ultracode の使い方**: DOM 確定後の実装・修正のたびに、多角レビュー＋敵対的検証を回すこと。
  特に「取り違え」（別の顧客に返信が飛ぶ）は営業上の事故になるため、`findRow`（会員IDでの行特定）
  と会員IDキーの安定性は最優先で検証する。
- **前セッションの限界**: 実機なしのレビューなので、「実DOMでは起きない/起きる」問題の見落としがあり得る。
  実機での最初の巡回は `ONLY_UNREAD=false`・顧客1〜2人のテスト環境（可能なら自分の LINE で友だち追加）で行うのが安全。

## 6. 環境メモ（Windows 固有の罠 — 前回レビューで確定したもの）

- Node **20.6 以上必須**（PM2 が `node --import tsx` で起動するため。doctor がチェックする）
- `pm2 start npm -- start` は **Windows で動かない** → 必ず `pm2 start ecosystem.config.cjs`
- `pm2 startup` は Windows 非対応 → `pm2-windows-startup` かタスクスケジューラ（RUNBOOK E）
- npm scripts に glob を書かない（cmd.exe は展開しない。test スクリプトは明示パス済み）
- headed ブラウザはログオン中のデスクトップセッションが必要
- `npm run chatid` を**本体稼働中に実行しない**（409 Conflict で本体のポーリングが落ちる。
  落ちた場合は明示終了→PM2 再起動する設計だが、避けるのが正しい）
